## 記法の早見表

### 行の先頭で決まるもの

| 書き方 | 意味 |
|---|---|
| `名前 \| パス \| 引数` | [項目](#項目)（メニューに 1 行出る） |
| `#` | [コメント](#行の種類)。行の途中の `#` はただの文字 |
| `@名前 = 値` | [別名](#別名)の定義 |
| `[.txt]` `[file folder]` | [セクション見出し](#セクション見出し)。ここから下の既定の対象 |
| `[extrun]` | [グローバル設定](#グローバル設定)の見出し |
| `\|` | [継続行](#複数行で書く)。直前の項目の続き |
| `:` | [名前付きフィールド](#名前付きフィールド)。直前の項目への追加指定 |
| `---` | [セパレーター](#セパレーター)（区切り線） |
| `>` `>>` | [サブメニュー](#サブメニュー)の階層 |
| `+` | [まとめて渡す](#行頭マーカー)（全パスを 1 プロセスへ） |

### 項目の中で使うもの

| 書き方 | 意味 |
|---|---|
| `名前 [+.svg -.jpg]` | [項目ごとの対象指定](#項目ごとの指定)。`+` は足し算、`-` は引き算、符号無しは完全置換 |
| `開く (&O)` | [アクセスキー](#アクセスキー)。`O` キーで実行できる |
| `:dir パス` | 作業フォルダ。未指定なら実行ファイルの場所 |
| `:confirm メッセージ` | [実行前の確認](#実行前の確認)ダイアログ（既定のボタンは「いいえ」） |
| `:icon パス,番号` | [名前の左に出すアイコン](#アイコン) |
| `:admin` | [管理者として実行する](#管理者として実行)（UAC の確認が出る） |
| `:delay ミリ秒` | [1 つずつの起動を空ける](#起動の間隔)。`0`（`off`）または `10`〜`10000` |
| `:wait` | [1 つずつ順に実行する](#1-つずつ順に実行)（前の 1 つが終了してから次を起動） |
| `%LOCALAPPDATA%` | [環境変数](#環境変数)。パスを書く欄（実行ファイル・`:dir`・`:icon`）でだけ展開される |

### 引数・作業フォルダ・`:confirm` の中で使うもの

| 書き方 | 置き換わるもの（例: `C:\folder\file.txt`） |
|---|---|
| `$p` | フルパス `C:\folder\file.txt` |
| `$-p` | 拡張子なしフルパス `C:\folder\file` |
| `$d` | 親ディレクトリ `C:\folder` |
| `$n` | ファイル名 `file.txt` |
| `$a` | 拡張子なしファイル名 `file` |
| `$f` | 親ディレクトリ名 `folder` |
| `$e` | 拡張子 `txt` |
| `$t{yyyyMMdd}` | [実行した日時](#日時)。`yyyy yy MM M dd d HH H mm m ss s` と曜日 `ddd`（土）`EEE`（Sat） |
| `$?{説明=既定値}` | [入力欄から設定した値](#入力欄)。`$?int` `$?num` `$?name` で[入力を絞れ](#入力値の決まり)、`$?list` で[選択肢から選べる](#選択肢から選ぶ) |
| `^X` | [エスケープ](#エスケープ)。`$ @ \| : > + - # [ ] & ^` の前に置くと記号そのものになる |

### `[extrun]` グローバル設定に書くもの

| 設定 | 意味 | 値 |
|---|---|---|
| `menu-position` | メニューを表示する位置 | `cursor`（既定）/ `window` / `screen` / `X,Y` |
| `select-first` | 先頭の項目を選択した状態で開くか | `no`（既定）/ `yes` |
| `icons` | アイコンを表示するか | `none` / `specified`（既定）/ `auto` |
| `delay` | [1 つずつの起動を空ける既定値](#起動の間隔)（ミリ秒） | `0`（既定。`off` も可）または `10`〜`10000` |
| `confirm-over` | [この数を超える起動で確認する](#件数が多いときの確認) | 件数（既定は `20`）/ `off` |

### コマンドライン

| 引数 | 意味 |
|---|---|
| `extrun.exe <パス>...` | メニューを表示する |
| `--at <位置>` | `menu-position` の挙動を[上書き](#コマンドライン引数で上書きする) |
| `--select-first` / `--no-select-first` | `select-first` の挙動を[上書き](#コマンドライン引数で上書きする) |
| `--check` | [設定ファイルを検証する](#設定の確認) |
| `--preview <パス>` | [メニューを起動せずにコマンドラインを表示する](#実行される内容の確認) |
| `--config <パス>` | [読み込む設定ファイルを切り替える](#設定ファイルを切り替える) |
| `--version` / `--help` | バージョン / 使い方 |

## ファイルの基本

| 項目 | 内容 |
|---|---|
| ファイル名 | `extrun-config.txt` |
| 置き場所 | `extrun.exe` と同じフォルダ（[`--config` で変えられる](#設定ファイルを切り替える)） |
| 文字コード | UTF-8（BOM の有無は問わない） |
| 改行 | CRLF / LF どちらでも可 |

メニューは**ファイルに書かれた順に上から下へ**表示される。

### 設定ファイルを切り替える

`--config` を付けると、読み込む設定ファイルを指定できる。**用途ごとに設定を分けたり、書き換えたものを本番の設定と入れ替えずに試したり**するためのもの。

```
extrun.exe --config D:\test\extrun-config.txt "C:\photo\a.jpg"
extrun.exe --check --config D:\test\extrun-config.txt
extrun.exe --preview --config D:\test\extrun-config.txt "C:\photo\a.jpg"
```

- **メニュー表示・`--check`・`--preview` のどれでも使える**
- 相対パスは**カレントディレクトリ基準**。`--config=パス` の書き方もできる
- 指定したファイルが無ければエラーになる（既定の設定ファイルへは戻らない）
- 作業フォルダの既定値（`:dir` を書かなかったときの実行ファイルの場所）など、他の解決は設定ファイルの位置に影響されない

「送る」に置くショートカットを複数作り、それぞれ別の `--config` を付けておけば、**用途別のメニューを並べられる**。

同梱のサンプル設定は、この仕様のほぼすべての書き方を使ってある。配布 zip では `extrun-config.sample.txt` という名前で入っているので、コピーして `extrun-config.txt` にリネームして使う。Windows 標準のコマンドだけで動くので、追加のインストールなしでそのまま試せる。

この文書は「何がどう書けるか」を定義するもので、「実際のアプリをどう書くか」は扱わない。ffmpeg・ImageMagick・IrfanView・7-Zip・VS Code・VLC・Pandoc などの具体的な設定例は **[extrun-recipes.md](extrun-recipes.md)（レシピ集）** にまとめてある。各レシピには「どの書式を使っているか」の注記が付いているので、仕様を読んで書き方は分かったが実際の形が思い浮かばない、というときはそちらが早い。

## 行の種類

行の先頭にある空白は常に無視される。字下げは見やすさのためだけのもので、意味を持たない。

| 行 | 意味 |
|---|---|
| `#` で始まる | コメント。行の途中の `#` はただの文字 |
| `@名前 = 値` | 別名の定義 |
| `[...]` だけの行 | セクション見出し（拡張子の既定値） |
| `[extrun]` | グローバル設定の見出し。ここから下は項目ではなく `名前 = 値` |
| `\|` で始まる | 直前の項目の続き（継続行） |
| `:` で始まる | 直前の項目の名前付きフィールド |
| `---` | セパレーター（区切り線） |
| それ以外 | 項目 |

## 項目

項目は3つのフィールドを `|` で区切って書く。

```
名前 | パス | 引数
```

| フィールド | 必須 | 説明 |
|---|---|---|
| 名前 | 必須 | メニューに表示される文字列 |
| パス | 実行する項目は必須 | 起動する実行ファイル |
| 引数 | 省略可 | 空白区切り。省略すると `$p` が渡される |

パスだけ、あるいは名前だけを書いてもよい。

```
VLC で再生する | C:\Program Files\VideoLAN\VLC\vlc.exe
```

**パスは絶対パスで書く。** 実行前に存在を確認し、見つからなければエラーダイアログになる。相対パスは起動元の作業フォルダ基準になるため、意図した場所を指さないことが多い。

パスに空白が含まれていても引用符は不要（`|` で区切られているため）。

```
VS Code で開く | C:\Program Files\Microsoft VS Code\Code.exe | -n $p
```

引数の中に空白を含めたい場合は引用符で囲む。

```
タイトル付きで開く | C:\Tools\viewer\viewer.exe | -title "My File" $p
```

引数欄を空にする（行末を `|` で終える）と、**引数なし**で起動する。省略した場合の `$p` とは区別される。

```
コマンドプロンプトで開く | C:\Windows\System32\cmd.exe |
 :dir $p
```

### アクセスキー

名前の中の `&` は、**次の 1 文字をアクセスキーにする印**。メニューが表示されているあいだにその文字を押すと、その項目が実行される。

```
開く (&O)          「開く (O)」と表示され、O キーで実行
&PNG に変換        「PNG に変換」と表示され、P キーで実行
```

`&` そのものは表示されず、キーになる文字に下線が付く。日本語の名前には `(&O)` を後ろに足す書き方が、英字を含む名前には頭の文字に直接付ける書き方が読みやすい。

- **半角英数字だけ**が使える。`&` の直後がそれ以外だとただの `&` として表示され、`--check` が警告する
- **大文字小文字は区別しない**。`(&o)` と書いても `O` キーで反応する
- 1 つの項目に付けられるキーは**1 つだけ**。2 つ目以降はただの `&` になり、`--check` が警告する
- 表示したい `&` は `^&` と書く（→ [エスケープ](#エスケープ)）

#### キーはメニューごとに独立している

アクセスキーが有効なのは、その項目が並んでいるメニューの中だけ。**親と子で同じ文字を使ってよい。**

```
圧縮 (&Z)
> &ZIP
>> 個別に圧縮 (&S)      | C:\Windows\System32\tar.exe | -a -c -f $-p.zip -C $d $n
>> + まとめて 1 つに (&A) | C:\Windows\System32\tar.exe | -a -c -f $d\archive.zip $p
> &TAR.GZ
>> 個別に圧縮 (&S)      | C:\Windows\System32\tar.exe | -a -c -f $-p.tar.gz -C $d $n
```

`Z` → `Z` → `S` の 3 打鍵で「ZIP で個別に圧縮」に届く。サブメニューの親のキーを押すとサブメニューが開くだけで、実行はされない。

#### 重複すると押しても動かない

同じメニューの中でキーが重複すると、押しても**実行されず、候補が順に選択されるだけ**になる（Windows の仕様）。押しても反応がないように見えるので、`--check` が重複を警告する。

**セクションが違ってもルートの項目は同じメニューに並ぶ**ことに注意。`[@画像]` の項目と `[folder]` の項目は、画像とフォルダをまとめて選択したときに同居する。ルート階層のキーは設定ファイル全体で重ならないようにする。

#### 下線が見えないとき

Windows は既定でアクセスキーの下線を隠すことがある。その場合は **Alt キーを押す**と現れる。下線が見えなくてもキー自体は効く。常に表示させたいときは、Windows の設定 →「アクセシビリティ」→「キーボード」→「アクセスキーに下線を表示する」を有効にする。

### 複数行で書く

`|` で始まる行は直前の項目の続きとして読まれる。1行スタイルと複数行スタイルは同じ意味で、同じファイル内で混在させてよい。

```
PNG を最適化する
 | C:\Tools\oxipng\oxipng.exe
 | -o max --strip all -a --out $-p_opt.png $p
```

上は次の1行と完全に同じ。

```
PNG を最適化する | C:\Tools\oxipng\oxipng.exe | -o max --strip all -a --out $-p_opt.png $p
```

## 名前付きフィールド

`:` で始まる行で、位置では表せない設定を書く。**必ず行頭に置く**（1行スタイルの途中には書けない）。

| キーワード | 説明 |
|---|---|
| `:dir` | 作業フォルダ。省略時は**実行ファイルの親フォルダ** |
| `:confirm` | 実行前に確認のダイアログを出す。値はメッセージ（省略可） |
| `:icon` | メニューに出すアイコン。値は `パス` または `パス,番号` |
| `:admin` | [管理者として実行する](#管理者として実行)。値は取らない |
| `:delay` | [1 つずつの起動を空ける](#起動の間隔)。値はミリ秒 |
| `:wait` | [1 つずつ順に実行する](#1-つずつ順に実行)。値は取らない |

**同じキーワードを 1 つの項目に 2 回書くとエラーになる。** どちらを使うかを順序で決める規則を作らないためで、書き間違い（直したつもりで古い行を消し忘れた、など）を `--check` で拾えるようにしてある。値を取らない `:admin` と `:wait` も同じ。

**`:dir` と `:icon` は値が要る。** キーワードだけを書くとエラーになる。`:confirm` だけは値なしを許す（メッセージを省いた確認ダイアログになる）。

`:dir` と `:confirm` の値では**プレースホルダーと別名が使える**。値は選択された最初の対象を基準に解決される。

**`:icon` で使えるのは別名とエスケープだけで、プレースホルダーは解決されない。** アイコンはメニューを組み立てる時点で読み込むもので、対象によって変わらないためである（`$p` などを書くと、その文字列がそのままパスとして扱われ、`--check` が「アイコンのファイルが見つかりません」と警告する）。

```
バックアップスクリプトを実行
 | C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
 | -NoProfile -ExecutionPolicy Bypass -File backup.ps1 -Path "$p"
 :dir C:\Tools\scripts
```

### 実行前の確認

`:confirm` を書いた項目は、選んだあと・起動する前に確認のダイアログを出す。「いいえ」を選ぶと何も起きない。

```
完全に削除する
 | C:\Windows\System32\cmd.exe
 | /c del /f /q "$p"
 :confirm $n を削除します。ごみ箱には入りません。
```

- **メッセージは省略できる**。`:confirm` とだけ書くと項目名を使った既定の文面になる
- **対象の一覧が必ず添えられる**。何をするかはメッセージで分かっても、何に対してするかは選び間違えているかもしれないので、目で確かめられるようにしてある
- **既定のボタンは「いいえ」**。`select-first` を有効にしていると Enter だけで実行まで進めてしまうが、確認を挟めばそのまま Enter を続けても止まる
- 確認は**項目に対して 1 回**。複数のファイルを選んでいても、対象の数だけ聞かれることはない
- サブメニューの親とセパレーターに書いても意味がない（選んでも実行されないため）。`--check` が警告する

#### 件数が多いときの確認

`:confirm` を書いていない項目でも、**起動する数が多いときは自動で同じ確認が出る**。フォルダの中身を全部選んだつもりが 300 個あった、というような選び間違いを、プロセスが 300 個並ぶ前に止めるための歯止めである。

しきい値は[グローバル設定](#グローバル設定)の `confirm-over` で決める。**既定は 20**（21 個目から確認が出る）。

```
[extrun]
confirm-over = 50     50 を超えたら確認する
confirm-over = off    確認しない
confirm-over = 0      常に確認する（0 件を超えたら、と読む）
```

- **数えるのは対象の数ではなく、起動するプロセスの数。** `+`（[まとめて渡す](#行頭マーカー)）を付けた項目は何個選んでも起動は 1 回なので、この確認は出ない
- 本文には、しきい値を超えたことと設定の現在値が出る。うるさいと感じたら数を上げるか `off` にする
- `:confirm` も書いてある項目では、**ダイアログは 1 枚にまとまる**。理由が 2 つあっても聞かれるのは 1 回
- `--preview` にも「確認します」と出る

### 管理者として実行

`:admin` を書いた項目は管理者として起動する。選ぶとユーザーアカウント制御（UAC）の確認が出て、「はい」を選んだときだけ実行される。

```
管理者としてコマンドプロンプトを開く | C:\Windows\System32\cmd.exe |
 :dir $p
 :admin
```

- **値は取らない。** `:admin` とだけ書く（`:admin yes` はエラー）
- **UAC をキャンセルすると何も起きない。** エラーにはならない
- 順番は**入力欄 → `:confirm` → UAC → 起動**
- サブメニューの親とセパレーターに書いても意味がない。`--check` が警告する

#### 複数選択したときは確認が対象の数だけ出る

**昇格はプロセスごとにしかできない。** 既定の「ファイルごとに別プロセス」で起動する項目に `:admin` を付けると、10 個選べば UAC が 10 回出る。

**`+`（まとめて渡す）と組み合わせるのが基本**で、こうすれば起動は 1 回、UAC も 1 回で済む。

```
+ まとめて属性を変える | C:\Windows\System32\attrib.exe | +r $p
 :admin
```

`+` の付いていない `:admin` の項目を複数の対象に対して選んだときは、**起動する前に「確認が N 回表示されます」と 1 回だけ知らせる**。そこで「いいえ」を選べば何も起きない。UAC を途中でキャンセルした場合も、残りの対象は起動されない。

この知らせは[実行前の確認](#実行前の確認)と同じダイアログに出る。`:confirm` や[件数の確認](#件数が多いときの確認)も重なるときは、理由が並んだ 1 枚にまとまる。

#### 環境変数とパスの解決

`%LOCALAPPDATA%` などの[環境変数](#環境変数)は、**昇格する前の（あなたの）環境で展開される**。管理者ユーザーのフォルダではなく、設定を書いた人のフォルダを指すので、`--preview` に出るパスがそのまま使われる。

### 起動の間隔

複数のファイルを選ぶと、既定では**ファイルごとに別プロセスが間を空けずに起動する**。`:delay` を書くと、1 つずつの起動のあいだに待ち時間が入る。

```
既定のアプリで開く | C:\Windows\explorer.exe | $p
 :delay 200
```

値はミリ秒で、**`0`（待たない）か `10`〜`10000`**。`0` は[グローバル設定](#グローバル設定)の `delay` を項目側で打ち消すために書く。`off` も `0` と同じ意味で書ける（`confirm-over` を無効にする語と揃えたいときのため）。

- 下限が `10` なのは、Windows のタイマーがそれ未満を切り上げるため。書いた値と実際が食い違わないよう、書けない値にしてある
- 上限があるのは書き間違いの歯止め。これが無いと `:delay 500000` と書いた設定が 8 分間ぶら下がる
- 待つのは起動と起動の**あいだ**。1 つ目はすぐ起動し、対象が 1 つなら待ち時間は発生しない
- サブメニューの親とセパレーターに書いても意味がない。`--check` が警告する

#### 何のための設定か

**同時に動くプロセスの数は減らない。** 20 個の動画を選んで 500 ミリ秒ずつ空けても、10 秒後には結局 20 個が同時に動いている。重い処理の負荷を抑えたいなら、`+`（まとめて渡す）で受け側にまとめて処理させるほうが確実である。

効くのは**起動が競合する場合**。

- **2 つ目以降を 1 つ目に渡す作りのアプリ**（ビューアやエディタによくある）。同時に叩くと、初期化の終わっていない相手に渡そうとして取りこぼされることがある
- **ウィンドウの重なる順**。同時に起動すると前後が運任せになるが、間隔があれば選んだ順に重なる

#### `+`（まとめて渡す）とは併用できない

`+` は何個選んでも 1 プロセスしか起動しないので、起動と起動のあいだが存在しない。書いても効かないので `--check` が警告する。

#### 待ちが長いときは進行状況が出る

**待ち時間の合計（`間隔 × (対象の数 - 1)`）が 1 秒以上になるとき**は、進行状況のダイアログが出る。これが無いと、待っているあいだ ExtRun は何も表示せずに生き続けることになり、終わったのか止まったのかも分からず、やめることもできない。

```
既定のアプリで開く を起動しています
7 / 20 を起動しました
中止できるのはまだ起動していない分だけです。

                          [一時停止] [以降の起動を取り消す]
```

- **一時停止**すると、その場で待ち時間が止まる。**再開**を押すと、間隔を待たずにすぐ次が起動する
- **以降の起動を取り消す**（Esc・× も同じ）と、**まだ起動していないぶんだけ**を取りやめる。**起動済みのプロセスは止まらない**（ExtRun は起動したプロセスを掴んでいない）
- UAC を断ったときも同じところで止まる

途中で止めると、何を起動して何が残ったかの要約が出る。**残りのパスはクリップボードに渡せる**ので、そのまま PowerShell に貼るなり、テキストエディタに貼って残すなりできる。ExtRun 自身は**ファイルを書き出さない**（書ける場所を ExtRun の側で決められないため、保存するかどうかは使う人が決める）。

どちらが起きるかは起動する前に決まるので、[`--preview`](#実行される内容の確認) に出る。

```
  起動の間隔　  300 ミリ秒（待ち 19 回で合計およそ 5.7 秒。進行状況を表示します）
```

### 1 つずつ順に実行

`:wait` を書くと、**起動したプロセスが終了してから次の 1 つを起動する**。`:delay` が起動をずらすだけなのに対し、こちらは終わるまで次を始めない。

```
サイズを調べる | C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
 | -NoProfile -NoExit -Command "..."
 :wait
```

`:admin` と同じく**書くか書かないかだけ**で、値は取らない。`:wait 5000` のように書くとエラーになる（隣に `:delay 300` があるので「5 秒まで待つ」と読まれかねず、黙って受けると待ち方が変わらないまま気づけないため）。

全体の既定値は無い。`:delay` と違って「その項目をどう使うか」の指定なので、書いた項目でだけ効く。

#### 効く場合と効かない場合

判断の分かれ目は、**起動されたプロセスが仕事を終えるまで生きているかどうか**。かかる時間の長短は関係しない。

- **効く** — 処理が終わると自分で終了するコマンドライン系のツール。そして**ユーザーが操作して閉じる GUI アプリも同じく効く**。10 分かけて編集してから閉じるアプリでも、その 10 分間プロセスは生きているので、閉じた時点で次が起動する
- **効かない** — 起動されたプロセスが数十ミリ秒で終了し、処理を別のプロセスへ引き継ぐもの。すでに開いているウィンドウに渡す単一インスタンス型のアプリ、ランチャー、`.lnk` 経由の起動など。この場合は間を置かずに次が起動する

効かない側に当たったときは、**そのアプリ自身が持つ「終了まで待つ」オプション**を探す（VS Code の `code --wait` など）。`cmd /c` を挟んでも、引き継ぎ先を待ってくれるようにはならない。どうしても待てない相手には `:delay` で間隔を空ける方が現実的である。

#### 手作業を挟むキューとして使う

`:wait` の使いどころは自動処理だけではない。**開く → 手で処理する → 閉じる → 次が開く**という流れを作れる。

30 枚の画像を 1 枚ずつ開いて手で切り抜きたいとき、まとめて選ぶと 30 枚が一度に開いて収拾がつかない。`:wait` を書いておけば、閉じるたびに次の 1 枚が出てくる。進行状況のダイアログが「何枚目か」を出し続けるので、どこまで進んだかも分かる。

#### 進行状況は必ず出る

対象が 2 つ以上あれば、**待ち時間の長短にかかわらず必ず**[進行状況のダイアログ](#待ちが長いときは進行状況が出る)が出る。

`:delay` と違って、終わるまでの時間は起動された側に委ねられていて、ExtRun には事前に分からない。だから「合計が短ければ出さない」という判断ができない。**待っているあいだ中止も一時停止もできない状態を作らないための約束**で、ExtRun が待ち続ける時間に上限を設けないことと引き換えになっている。

```
サイズを調べる を 1 つずつ実行しています
7 / 30 を起動しました（実行中のものが終わるのを待っています）
実行中のものが終了すると、次の 1 つが起動します。
中止できるのはまだ起動していない分だけです。

                          [一時停止] [以降の起動を取り消す]
```

- **一時停止**すると、いま動いているものが終わっても次を起動しない。手作業を途中で中断したいときに使う
- **以降の起動を取り消す**は `:delay` のときと同じ意味で、**いま実行中のものは終了しない**（自分で閉じる）

このダイアログの題名には**項目名が入る**（`サイズを調べる ― ExtRun`）。`:wait` では終わるまでの時間が長くなりやすく、そのあいだに別の ExtRun を起動することもあるので、タスクバーで見分けられるようにしてある。ExtRun は多重起動しても互いに干渉しない。

#### `+`（まとめて渡す）とは併用できない

`+` は何個選んでも 1 プロセスしか起動しないので、待つ相手がいない。書いても効かないので `--check` が警告する。サブメニューの親とセパレーターに書いた場合も同じ。

#### `:delay` と併記できる

両方書くと、**終了を待ってから、さらに `:delay` の間隔を空けて**次を起動する。効かない相手（上の「引き継ぐ」タイプ）に当たったときの保険として使える。

[`--preview`](#実行される内容の確認) には次のように出る。合計時間を書かないのは、終わるまでの時間が ExtRun には分からないため。

```
  起動の順番　  1 つずつ実行（:wait。前の 1 つが終了してから次を起動します。進行状況を表示します）
  起動の間隔　  300 ミリ秒（:wait で終了を待ったあと、さらにこれだけ空けます）
```

### アイコン

`:icon` を書いた項目には、名前の左にアイコンが出る。

```
開く (&O)
 :icon C:\Windows\System32\imageres.dll,3
> 既定のアプリで開く (&D) | C:\Windows\explorer.exe | $p

PNG を最適化する | C:\Tools\oxipng\oxipng.exe | -o max --out $-p_opt.png $p
 :icon C:\Tools\oxipng\oxipng.exe
```

- 値は **`パス`** または **`パス,番号`**。番号は dll や exe に複数のアイコンが入っているときに選ぶ（`.reg` やショートカットと同じ書き方）。省略すると 0
- **最後のコンマの後ろが整数のときだけ**番号と見なすので、`C:\dir,1\a.ico` のようにパスの途中にコンマがあっても取り違えない
- 別名が使える。`^` によるエスケープも実行ファイルのパスと同じように効く
- **サブメニューの親にも付く**（`:confirm` と違って意味がある）。セパレーターには付かない
- 出るかどうかは `[extrun]` の `icons` 次第。既定の `specified` なら、`:icon` を書いた項目だけに出る

`.ico` ファイルのほか、アイコンを持つ `.exe` や `.dll` を指定できる。Windows 標準のアイコンは `C:\Windows\System32\imageres.dll` と `shell32.dll` にまとまっているので、番号を変えて選ぶとよい。

`--check` は**実際に取り出せるかまで確かめる**。ファイルが無いときだけでなく、番号が範囲の外のときも警告する（パスは正しいのにアイコンだけ出ない、という分かりにくい状態を防ぐため）。どちらも警告なので、メニュー自体は表示される。

> [!NOTE]
> アイコンの大きさは、メニューを出すモニタの DPI に合わせて決まる。Per-Monitor V2 ではメニューの文字や枠は自動で拡大されるが、渡したビットマップは拡大されないため、ExtRun 側で計算している。

## 行頭マーカー

名前の前に置いて項目の性質を指定する。**後ろに空白が続くときだけ**マーカーとして働くので、`+新規作成` のような名前はそのまま書ける。

| マーカー | 意味 |
|---|---|
| `>` | サブメニューの1階層目 |
| `>>` | サブメニューの2階層目（以降 `>>>`…と重ねる） |
| `+` | 複数選択時、すべてまとめて1プロセスに渡す |

`+` を付けない場合は、選択された各ファイルごとに個別のプロセスが起動する（既定の動作）。

`+` が有効なのは、複数の入力を引数に並べて受け取れるアプリに限られる。7-Zip の圧縮、ImageMagick の `+append`、VS Code の `--diff`、VLC のプレイリストなどが該当する。逆に ffmpeg の `-i $p` のように入力ごとにオプションが必要なアプリでは、`-i a.mkv b.mkv` に展開されて意図どおりにならない。実例は `extrun-recipes.md` の「2-8. `+`（まとめて渡す）が向くもの・向かないもの」を参照。

### サブメニュー

パスを持たない項目が親になり、それより深い階層の項目が子になる。閉じ記号は不要で、階層が浅い行が現れた時点でサブメニューは終わる。

```
圧縮
> 7-Zip
>> + まとめて 1 つにする | C:\Program Files\7-Zip\7z.exe | a -t7z $d\archive.7z $p -mx9
>> 個別に圧縮           | C:\Program Files\7-Zip\7z.exe | a -t7z $-p.7z $p -mx9
> ---
> ZIP
>> 個別に圧縮           | C:\Program Files\7-Zip\7z.exe | a -tzip $-p.zip $p
```

### セパレーター

`---` だけの行。サブメニューの中では階層マーカーを付ける。

```
---          親階層のセパレーター
> ---        サブメニュー1階層目のセパレーター
>> ---       サブメニュー2階層目のセパレーター
```

先頭・末尾のセパレーターと、連続したセパレーターは表示時に自動で取り除かれる。

## セクションと拡張子

### セクション見出し

`[...]` だけの行。以降の項目が既定で対象とする拡張子を指定する。**項目より前に必ず1つ以上のセクション見出しが必要**。

```
[.txt]

メモ帳で開く   | C:\Windows\notepad.exe
VS Code で開く | C:\Program Files\Microsoft VS Code\Code.exe | -n $p
```

同じセクション見出しをファイル内に何度書いてもよい。

| 書き方 | 対象 |
|---|---|
| `.txt` | 拡張子が txt のファイル（先頭の `.` は必須） |
| `file` | すべてのファイル（フォルダを除く） |
| `folder` | フォルダ |
| `[file folder]` | すべてのファイルとフォルダ |

大文字小文字は区別しない。

### 項目ごとの指定

名前の直後に `[...]` を書くと、その項目だけ対象を変えられる。**書き方は4通り**。

**1. 何も書かない** — セクションの指定をそのまま受け継ぐ。大半の項目はこれで済む。

```
[.wav .flac .mp3 .m4a .opus]

VLC で再生する | C:\Program Files\VideoLAN\VLC\vlc.exe
```

**2. 引き算** — `-` を付けたものを、受け継いだものから取り除く。

```
[.png .jpg .jpeg .gif .bmp .webp .avif .svg]

JPEG に変換 [-.jpg -.jpeg] | ...
```

**3. 足し算** — `+` を付けたものを、受け継いだものに加える。

```
[.png .jpg .jpeg .gif .bmp .webp .avif]

アイコンに変換 [+.svg] | ...
```

**4. 完全置換** — 符号の付かない項目が1つでもあれば、受け継いだものを無視して置き換える。

```
[.png .jpg .jpeg .gif .bmp .webp .avif .svg]

アイコンに変換 [.svg] | ...
```

足し算と引き算は同じ `[...]` の中に混ぜてよい。どちらも「受け継いだものからの差分」なので、向き以外の扱いは同じ。

```
ベクタだけ別扱い [+.svg +.eps -.jpg] | ...
```

**符号（`+` / `-`）付きと符号なしは混ぜられない**（エラーになる）。差分を書くのか置き換えるのかが決まらないため。同じ拡張子に `+` と `-` の両方を書いた場合もエラーになる。

すでに受け継いでいる拡張子を `+` で足しても重複しない。受け継いでいない拡張子を `-` で引いても何も起きない。

**引き切って空にすると「すべての対象」になる。** 対象の指定が空の項目はどの対象でも表示される決まりなので、`[.txt]` のセクションで `[-.txt]` と書くと、txt を外すどころか**すべてのファイルとフォルダで出る**ようになる。意図と正反対になるうえ黙って起きるので、`--check` が警告する。

```
[.txt]

X [-.txt] | ...      ← 警告。すべての対象で表示される
```

セクション見出しの中では足し算・引き算は使えない（継承元がないため）。

**別名と組み合わせるときは符号を各要素に付ける。** 別名は展開されてから空白で区切られるので、`@画像 = .png .jpg` に対する `[+@画像]` は `[+.png .jpg]` になり、混在のエラーになる。

**セクションの指定は「既定値」であって「絞り込み条件」ではない。** セクションが `[folder]` でも、その中の項目に `[folder .png]` と書けばその項目は PNG でも表示される。セクションに中の項目の拡張子をすべて含める必要はない。

セパレーターも拡張子を持てる。

```
--- [folder .png]
```

## 別名

`@名前 = 値` の形で定義する。**ファイル内のどこに書いてもよく、どこからでも使える**（後ろで定義したものを前で使ってもよい）。

```
@apps  = C:\Program Files
@tools = C:\Tools
@7z    = @apps\7-Zip\7z.exe
@画像  = .png .jpg .jpeg .gif .bmp .webp .avif .svg
```

別名の中で別名を使える（`@7z` の例）。

使える場所はすべてのフィールド（名前・パス・引数・作業フォルダ・拡張子）。

```
[@画像]

WebP に変換 | @tools\libwebp\bin\cwebp.exe | $p -o $-p.webp
アイコンに変換 [.svg] | @tools\Python\python.exe | @tools\scripts\svg_to_ico.py $p
```

### 別名の名前がどこで終わるか

`@` の後ろは、次のいずれかが現れるまでが名前として読まれる。

```
空白  \  |  [  ]  ^  @  行末
```

パスの途中に置けるのはこのためで、`@tools\sub\a.exe` は `@tools` + `\sub\a.exe` になる。

**引用符では終わらない**ことに注意。`'@tar'` と書くと `tar'` という名前の別名を探しにいって「未定義」のエラーになる。引用符で囲みたい場合は、`\` を含む形にするか、別名を使わずに書く。

```
NG   & '@tar' -x -f '$p'
OK   & '@sys\tar.exe' -x -f '$p'
```

| 規則 | 動作 |
|---|---|
| 同じ名前を2回定義 | エラー |
| 定義されていない `@名前` を使用 | エラー |
| 別名が循環している | エラー |

`@` という文字そのものを書きたい場合は `^@` を使う。

```
リストファイルから圧縮 | @7z | a -t7z $-p.7z ^@filelist.txt
```

## 環境変数

パスの中の `%NAME%` は環境変数の値に置き換わる。ユーザー名がパスに入るアプリを、**設定ファイルを書き換えずに別の PC でも使える**ようにするためのもの。

```
@vscode = %LOCALAPPDATA%\Programs\Microsoft VS Code\Code.exe
@win    = %SystemRoot%
```

### 展開されるのはパスを書く3か所だけ

| 欄 | 展開 |
|---|---|
| 実行ファイル（2番目のフィールド） | される |
| `:dir` | される |
| `:icon` | される |
| **引数** | **されない** |
| 名前・拡張子の指定 | されない |

引数欄で展開しないのは、`cmd.exe /c` に渡す `%errorlevel%` や、バッチの `%~n1` を横取りしないため。これらは**書いたままインタプリタに渡される**。

```
エラーレベルを表示 | @cmd | /k echo %errorlevel%      ← そのまま cmd に渡る
```

**展開するかどうかは「どの欄か」で決まり、別名かどうかでは決まらない。** `@apps = %ProgramFiles%` と定義した別名は、パス欄で使えば展開され、引数欄で使えば `%ProgramFiles%` のまま渡る。

### 決まり

- **未定義の変数はそのまま残る**（`%FOO%` という文字列になる）。パスが解決できないので `--check` が「実行ファイルが見つかりません: `%FOO%\app.exe`」と警告し、展開されていないことがそこで分かる
- **大文字小文字は区別しない**。`%systemroot%` でも `%SystemRoot%` でも同じ
- `%%` や閉じ忘れの `%` はそのまま残る。`C:\100%\app.exe` のようなパスはそのまま書ける
- 展開は**設定ファイルを読み込む時点**で済む。`--check` の存在確認も `--preview` の表示も展開後の値になる

対象のファイル名に含まれる `%` は展開されない。`$p` などのプレースホルダーは実行時に解決されるので、`100%OFF.png` のような名前がそのまま扱われる。

## 値の埋め込み

項目の**引数**・**作業フォルダ**・**`:confirm` のメッセージ**の中には、実行のたびに中身が決まる値を書き込める。この章の 4 つはどれもその仲間で、同じ場所に混ぜて書ける。

| 記法 | 何に置き換わるか | 節 |
|---|---|---|
| `$p` `$-p` `$d` `$n` `$a` `$f` `$e` | 対象のパスの各部分 | [プレースホルダー](#プレースホルダー) |
| `$t{...}` | 実行した日時 | [日時](#日時) |
| `$?{...}` | 実行する前に入力欄で設定した値 | [入力欄](#入力欄) |
| `^X` | 記号そのもの（置換をさせない） | [エスケープ](#エスケープ) |

解決される順序は**入力欄で聞く → エスケープと置換をまとめて処理 → 起動**。エスケープと置換は 1 回の走査で同時に行われるので、`^$p` は「`$p` という文字列」になり、そこからさらに置換されることはない。

---

### プレースホルダー

引数と作業フォルダの中で使える。

| 記号 | 内容 | 例（`C:\folder\file.txt`） |
|---|---|---|
| `$p` | フルパス | `C:\folder\file.txt` |
| `$-p` | 拡張子なしのフルパス | `C:\folder\file` |
| `$d` | 親フォルダのパス | `C:\folder` |
| `$n` | 名前（拡張子付き） | `file.txt` |
| `$a` | 名前（拡張子なし） | `file` |
| `$f` | 親フォルダの名前 | `folder` |
| `$e` | 拡張子 | `txt` |

続けて書けるので、出力先の組み立てに使える。

```
$-p_opt.png        →  C:\folder\file_opt.png
$d\$a_small.$e     →  C:\folder\file_small.txt
```

`$` という文字そのものを書きたい場合は `^$` を使う。

`+`（まとめて渡す）が付いている項目では、`$p` の位置に選択されたすべてのパスが展開される。引数に `$p` が含まれない場合は末尾にすべてのパスが追加される。

ただし**引数欄を空にした（行末を `|` で終えた）場合は引数なしのまま**で、パスは追加されない。欄を空にするのと欄ごと省略するのは `+` でも区別される（[引数](#引数)を参照）。

展開されるのは **`$p` を独立した 1 つの引数として書いたとき**だけ。`-i$p` のように他の文字とつなげて書いた場合は、最初に選ばれた対象を基準に置換されるだけで、残りのパスはどこにも渡らない（`--check` が警告する）。`$p` 以外のプレースホルダー（`$d` や `$n` など）は、`+` の有無にかかわらず常に最初の 1 つが基準になる。

```
+ まとめて圧縮 | @7z | a -t7z $d\archive.7z $p -mx9     全パスが $p の位置に並ぶ
+ まとめて開く | @vlc | --playlist-enqueue              末尾に全パスが追加される
+ 変換         | @ffmpeg | -i$p out.mp4                  最初の 1 つしか渡らない（警告）
```

### 日時

`$t{...}` は**実行した日時**に置き換わる。中括弧の中に書式を書く。

```
バックアップ | @tar | -a -c -f $-p_$t{yyyyMMdd}.zip -C $d $n
        →  -a -c -f C:\folder\file_20260815.zip -C C:\folder file.txt
```

#### 書式文字

| 書式 | 内容 | 例（2026-08-15 土曜 14:03:05） |
|---|---|---|
| `yyyy` / `yy` | 年 | `2026` / `26` |
| `MM` / `M` | 月（**大文字**） | `08` / `8` |
| `dd` / `d` | 日 | `15` / `15` |
| `HH` / `H` | 時（24 時間制） | `14` / `14` |
| `mm` / `m` | 分（**小文字**） | `03` / `3` |
| `ss` / `s` | 秒 | `05` / `5` |
| `ddd` / `dddd` | 曜日（日本語） | `土` / `土曜日` |
| `EEE` / `EEEE` | 曜日（英語） | `Sat` / `Saturday` |

2 文字の方は 0 で桁を埋める。月が `MM` で分が `mm` なのは PowerShell の `Get-Date -Format` と同じ。

> [!WARNING]
> **`d` は文字数で意味が変わる。** `d` と `dd` は日、`ddd` と `dddd` は曜日。

#### 書き方

英字でない文字はそのまま通るので、区切りをそのまま書ける。

```
$t{yyyy-MM-dd}          →  2026-08-15
$t{yyyy年MM月dd日}      →  2026年08月15日
$t{yyMMdd_HHmm}         →  260815_1403
$t{yyyyMMdd(ddd)}       →  20260815(土)
```

**中括弧の中に書けるのは書式文字と英字以外の文字だけ**で、それ以外の英字はエラーになる。日付以外の文字は中括弧の外に出す。

```
NG   $t{yyyyMMdd_backup}
OK   $t{yyyyMMdd}_backup
```

`$t` は**中括弧が続いたときだけ**日時として扱われる。`$t` 単独や `100$t` はそのまま残る。

日時を書くたびに書式を並べるのが煩わしければ、別名にできる。

```
@today = $t{yyyyMMdd}

バックアップ | @tar | -a -c -f $-p_@today.zip -C $d $n
```

#### 時刻が決まるタイミング

**メニューの項目を選んだ時点**の時刻が使われ、その 1 回の実行の中では**すべての対象で同じ値**になる。複数のファイルを選んで個別に起動した場合も、`$t{ss}` は全部同じ秒になるので、まとめて作ったファイルの名前が揃う。

書式の書き間違いは `--check` がエラーとして報告し、メニューは表示されない。誤った文字列がそのままファイル名になるのを防ぐため、警告ではなくエラーにしている。

### 入力欄

`$?{...}` は、項目を選んだあとに**入力欄を出して、入力された文字に置き換わる**。値をひとつ変えたいだけの項目を、解像度や品質の数だけ並べずに済む。

```
長辺を指定して縮小 | @magick | $p -resize $?{長辺のピクセル数=1280}x$?{長辺のピクセル数=1280}^> $-p_small.png
```

中括弧の中は `説明=既定値` の形で、**最初の `=` で分かれる**。既定値は省略できる。

```
$?{新しい名前}              説明だけ
$?{長辺のピクセル数=1280}   既定値つき
$?{品質 = 85}               = のまわりの空白は無視される
```

- **既定値は選択された状態で入る**。そのまま打てば置き換わり、Enter だけなら既定値がそのまま使われる
- **同じ内容の `$?{...}` は 1 回しか聞かれない**。上の例のように、入力した値を引数の複数の場所で使える
- **キャンセルすると何も実行されない**。複数の入力欄があるときは、そのうちひとつをキャンセルした時点で打ち切る
- 説明と既定値の中では**プレースホルダーと日時が使える**（`$?{$n の新しい名前=$a_$t{yyyyMMdd}}`）。値は選択された最初の対象を基準に解決される
- `$?{...}` を入れ子にはできない（`--check` がエラーにする）
- `$?` は**中括弧が続いたときだけ**入力欄になる。PowerShell の `$?`（直前のコマンドの成否）はそのまま渡る

順番は、**入力欄 → 確認（`:confirm`）→ 起動**。確認のメッセージにも `$?{...}` を書けるので、入力した値を確かめてから実行できる。

```
書き出す | @magick | $p -quality $?{品質=85} $-p_out.jpg
 :confirm 品質 $?{品質=85} で書き出します。
```

> [!NOTE]
> 引数は空白で区切られるが、**`$?{...}` と `$t{...}` の中括弧の中は区切られない**。`$?{$n の新しい名前}` のように空白を含む説明をそのまま書ける。

`--preview` は入力欄を出せないので、既定値（無ければ `<説明>`）で埋めた形を表示する。

#### 入力値の決まり

`$?` と `{` のあいだに書くと、入力できる値を絞れる。

| 書き方 | 受け付ける値 |
|---|---|
| `$?{...}` | 制限なし |
| `$?int{...}` | 整数（`1280` `-5`） |
| `$?num{...}` | 数値（`1.5` `-2` `0.25`） |
| `$?name{...}` | ファイル名に使える文字 |
| `$?list{...}` | [並べた選択肢から選ぶ](#選択肢から選ぶ)（打ち込めない） |

```
長辺を指定して縮小 | @magick | $p -resize $?int{長辺のピクセル数=1280} $-p_small.png
名前を付けて複製   | @cmd    | /c copy "$p" "$d\$?name{新しい名前=$a}.$e"
```

##### 選択肢から選ぶ

取りうる値が決まっているときは、`$?list{...}` で選択肢を並べられる。`=` の右側を `,` で区切ったものが選択肢になり、**先頭が最初から選ばれた状態**で開く。

```
JPEG で書き出す | @magick | $p -quality $?list{品質=85,95,100} $-p_out.jpg
形式を選んで変換 | @magick | $p $-p_out.$?list{形式=png,jpg,webp}
```

前後の空白は落とされるので `85, 95, 100` と読みやすく並べてよい。**選択肢そのものに `,` は書けない。** 区切りに `|` を使わないのは、[欄の区切り](#1-行スタイル)と重なって `^|` と書かせることになるため。

一覧から選ぶだけなので**入力の検証は要らない**（打ち込めないため、決まりを満たさない値を作れない）。選択肢を 1 つも書かないと `--check` がエラーにする。

**決まりを満たさない入力は、打ち切らずに聞き直す。** 理由を添えて、打った内容が残った状態で入力欄が出直る。キャンセルすれば実行しない点は変わらない。

`$?name{...}` が弾くもの:

- 空
- ファイル名に使えない文字（`\ / : * ? " < > |` と制御文字）
- 終わりの `.` と空白
- Windows が予約している装置名（`CON` `PRN` `AUX` `NUL` `COM1`〜`COM9` `LPT1`〜`LPT9`。`CON.txt` のように拡張子を付けても使えない）
- 255 文字を超える名前（NTFS の名前 1 要素の上限）

> [!NOTE]
> `$?name{...}` が見るのは**名前 1 つぶんの決まり**だけで、パス全体の長さ（`MAX_PATH`）は見ない。入力した値がパスのどこに入るのかを ExtRun は知らないため。

`$?int{...}` は全角数字（`１２８０`）や単位付き（`1280px`）も弾く。数値と名前では前後の空白を落としてから渡す（制限なしのときは打たれたとおりに渡す）。

**既定値も `--check` が検証する。** `$?int{品質=たかい}` のような書き間違いは、実行する前に見つかる。ただし既定値にプレースホルダーが入っている場合（`$?int{幅=$e}`）は実行するまで値が決まらないので検証しない。

正規表現や文字数の指定は用意していない。正規表現エンジンは依存クレートが増えるため入れない方針で、それ以外の細かい制約は `:confirm` で入力値を見せて確かめる形にする。

```
書き出す | @magick | $p -quality $?int{品質=85} $-p_out.jpg
 :confirm 品質 $?int{品質=85} で書き出します。
```

### エスケープ

`^` を特殊文字の前に置くと、その文字は普通の文字として扱われる。

| 書き方 | 結果 |
|---|---|
| `^>` `^+` | 記号で始まる項目名 |
| `^\|` | 区切りにしない `\|` |
| `^:` | 名前付きフィールドにしない `:` |
| `^@` | 別名として解決しない `@` |
| `^$` | プレースホルダーにしない `$` |
| `^+` `^-` | 足し算・引き算にしない `+` `-`（拡張子欄） |
| `^&` | アクセスキーにしない `&`（名前欄） |
| `^#` `^[` `^]` `^^` | それぞれの文字そのもの |

PowerShell のワンライナーのように `|` と `$` の両方を含む引数では、まとめて使うことになる。

```
ファイル一覧を書き出す
 | C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
 | -NoProfile -Command "Get-ChildItem -LiteralPath '$p' ^| ForEach-Object { ^$_.FullName }"
```

**`-Command` に渡すコマンドは、全体を `"..."` で囲んで 1 つの引数にする。** 囲まずに空白で区切ると複数の引数に分かれ、PowerShell 側で結合し直されるときに引用の扱いが変わって、空白を含むパスで壊れる。囲んだ中では `'...'`（単引用符）を使う。`"` は引数の区切りとして解釈されるので、コマンドの中には書けない。

**`^` は特殊文字の前に置かれたときだけエスケープとして働く。** それ以外の場所ではただの `^` なので、`C:\Foo^Bar\app.exe` のようなパスをそのまま書ける。

名前の**途中**にある記号はエスケープ不要。行頭マーカーは名前が始まった時点で解釈を終えるため。

```
JPEG > PNG に変換 | @irfan | $p /convert=$-p.png
画像 + 動画をまとめる | C:\Tools\merge\merge.exe
```

引数の中で特殊なのは `"`（引用符）・空白・`^` によるエスケープだけで、それ以外の記号はそのまま書ける。ffmpeg の `-filter_complex fps=12,scale=480:-1:flags=lanczos,split[a][b];[b]palettegen[p];[a][p]paletteuse` や、ImageMagick の `-resize 1280x1280>` のような値も、エスケープなしでそのまま通る（空白を入れると別の引数に分かれてしまう点だけ注意）。実例は `extrun-recipes.md` を参照。

## グローバル設定

`[extrun]` は拡張子の見出しではなく、**ExtRun 自体のふるまい**を書く場所。ここから下の行は項目ではなく `名前 = 値` として読まれ、次の拡張子セクションが来ると項目に戻る。

```
[extrun]
menu-position = window
select-first  = yes

[@画像]
開く (&O) | C:\Windows\explorer.exe | $p
```

拡張子セクションと違い、**ファイルのどこに書いても全体に効く**（順番に意味はない）。

| 名前 | 値 | 既定 | 意味 |
|---|---|---|---|
| `menu-position` | `cursor` / `window` / `screen` / `X,Y` | `cursor` | メニューを表示する位置 |
| `select-first` | `yes` / `no` | `no` | 先頭の項目を選択した状態で開くか |
| `icons` | `none` / `specified` / `auto` | `specified` | アイコンを表示するかどうか |
| `delay` | `0`（`off`）または `10`〜`10000` | `0` | 1 つずつの起動を空けるミリ秒 |
| `confirm-over` | 件数 / `off` | `20` | この数を超える起動で確認する |

`menu-position` の値:

| 値 | 位置 |
|---|---|
| `cursor` | マウスカーソルの位置 |
| `window` | ExtRun を呼んだときに前面だったウィンドウの中央 |
| `screen` | そのウィンドウがあるモニタの中央（タスクバーを除く） |
| `X,Y` | 画面座標を直接指定。例 `100,200`。マルチモニタでは負の値もありうる |

座標は**物理ピクセル**。ウィンドウが最小化されているなど基準にできないときは、画面中央 → カーソル位置の順にフォールバックされる。

`select-first = yes` にすると、メニューが開いた時点で先頭の項目が選択されているので、そのまま Enter で実行できる。

`icons` の値:

| 値 | 動き |
|---|---|
| `none` | 表示しない。`:icon` を書いていても無視する |
| `specified` | `:icon` を書いた項目だけ表示する（既定） |
| `auto` | `:icon` を優先し、書いていない項目は実行ファイルから取り出す |

既定が `specified` なので、`:icon` を 1 つも書いていない設定では**アイコンの読み込みが一切走らない**（起動時間はこれまでと変わらない）。それでいて `:icon` を書けばすぐ効く。

`none` は「設定は残したまま、しばらく出したくない」ときのためのもの。

`auto` は項目ごとに実行ファイルからアイコンを取り出すぶん、メニューが出るまでが少し遅くなる。

`delay` は[起動の間隔](#起動の間隔)の既定値で、`:delay` を書いていない項目に効く。項目側に `:delay` があればそちらが勝ち、`:delay 0` と書けば打ち消せる。

**[`:wait`](#1-つずつ順に実行) にはこれに当たる既定値が無い。** 全体に効かせると、複数のファイルを選んだだけで ExtRun が終了を待ち続ける項目が意図せず増えるためで、書いた項目でだけ効く。

`confirm-over` は[件数が多いときの確認](#件数が多いときの確認)のしきい値。**この設定だけは既定で有効**（`20`）で、守る相手が「件数を意識していない人」だからである。書いた人だけが守られる安全装置は、うっかりミスをまさに防ぎたい場面で効かない。

無効にするのは `off` で、`0` ではない（`0` は「0 件を超えたら」＝常に確認、と読む）。`delay` の方も揃えて `off` と書ける（`0` と同じ意味）。

### コマンドライン引数で上書きする

**表示位置と初期選択は「設定ファイルの属性」ではなく「呼び出し方の属性」。** 右クリックメニューから呼ぶときはカーソル位置が正しいが、ホットキーから呼ぶときはマウスがどこにあるか分からない。設定ファイルは 1 つのまま、呼び出しごとに変えられる。

| 引数 | 意味 |
|---|---|
| `--at <位置>` / `--at=<位置>` | `menu-position` を上書き |
| `--select-first` | 先頭を選択して開く |
| `--no-select-first` | 選択しないで開く（設定の `yes` を打ち消す） |

```
extrun.exe "%1"                              右クリック登録（設定ファイルのまま）
extrun.exe --at window --select-first "%1"   ホットキーから
```

指定しなかった項目は設定ファイルの値がそのまま使われる。値が不正なときはエラーダイアログを出して終了コード 1 で終わる。

## 設定の確認

```
extrun.exe --check
```

書式のエラー、別名の重複や未定義、実行ファイルが見つからないパスなどを行番号付きで一覧表示する。設定を編集したら実行して確かめるとよい。

同梱のサンプルをそのまま検証すると `問題は見つかりませんでした` と表示される。自分のアプリを書き足したあと、「実行ファイルが見つかりません」の警告が出たらパスの綴りを疑うとよい。これは警告であって書式のエラーではないので、メニュー自体は表示される。

| 種別 | 意味 | メニュー |
|---|---|---|
| エラー | 書式が壊れている（別名の重複・循環、階層飛び、先頭の `.` 抜け、`[extrun]` の未知の設定や不正な値など） | 表示されない |
| 警告 | 書けてはいるが意図と違う可能性がある（パスなし、実行ファイルが見つからない、スクリプトの直接指定、`+` の `$p` の書き方、効かない場所に書いた `:delay` / `:wait` / `:admin` / `:confirm`、アクセスキーの重複や書き間違い、[引き切って空になった拡張子指定](#項目ごとの指定)） | 表示される |

終了コードはエラーがあれば 1、それ以外は 0。バッチファイルからはそのまま `if errorlevel 1` で判定できる。PowerShell は `extrun.exe` の終了を待たないので、`Start-Process -Wait -PassThru` の `ExitCode` を見る。

## 実行される内容の確認

```
extrun.exe --preview <パス> [パス ...]
```

`--check` が書式を見るのに対して、`--preview` は**そのパスに対して実際に何が起動されるか**を、起動せずに表示する。プレースホルダーとエスケープが意図どおりに解決されているかを、プロセスを走らせずに確かめられる。

```
> extrun.exe --preview "C:\photo\a.jpg"
対象:
  C:\photo\a.jpg  (.jpg)

形式を変換 (C) > PNG に変換
  実行ファイル  C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
  引数　　　　  -NoProfile
  引数　　　　  -Command
  引数　　　　  Add-Type -AssemblyName System.Drawing; ...
  作業フォルダ  C:\Windows\System32\WindowsPowerShell\v1.0  （:dir 未指定のため実行ファイルの場所）

15 項目
```

見るときの要点：

- **引数は 1 つ 1 行**。PowerShell に渡す長い 1 引数と、複数の引数に割れてしまったものを見分けられる。`"..."` で囲み忘れて空白で割れている項目は、ここで気づける
- **作業フォルダ**は解決後の値。`:dir` を書いていない項目には実行ファイルの親ディレクトリが入るので、その旨が添えられる
- **サブメニューは `親 > 子` の形**で平坦に並ぶ。実行されない親項目とセパレーターは出ないので、末尾の項目数は `--check` やメニューの見た目より少なくなる
- **複数のパスを渡すと起動の回数が分かる**。個別実行の項目は `[1/2]` `[2/2]` と対象の数だけ並び、`+`（まとめて渡す）の項目は 1 回の起動に全パスが並ぶ
- **[起動の間隔](#起動の間隔)を書いた項目には、待ち時間の合計と進行状況を出すかどうかが並ぶ**。どちらになるかは起動する前に決まるので、ここで先に読める
- **[`:wait`](#1-つずつ順に実行) を書いた項目には「1 つずつ実行」の行が並ぶ**。合計時間は出ない（終わるまでの時間は起動された側に委ねられていて、ExtRun には分からない）

設定ファイルにエラーがあるときは、メニューを組み立てられないので一覧の代わりにエラーを表示して終了コード 1 で終わる。項目を名前で絞り込む機能は無いので、数が多いときは `Select-String` などに通す。

## 完全な例

```
# --- 別名 ---
@apps   = C:\Program Files
@tools  = C:\Tools
@irfan  = @apps\IrfanView\i_view64.exe
@cwebp  = @tools\libwebp\bin\cwebp.exe
@画像   = .png .jpg .jpeg .gif .bmp .webp .avif .svg


# --- 画像 ---
[@画像]

形式を変換 (&C)
> &JPEG に変換 [-.jpg -.jpeg]
 | @irfan
 | $p /convert=$-p.jpg
> &PNG に変換 [-.png]
 | @irfan
 | $p /convert=$-p.png
> ---
> + アイコンに変換 (&I) [.svg]
 | @tools\Python\python.exe
 | @tools\scripts\svg_to_ico.py $p

&WebP に変換 [-.webp -.avif -.svg]
> 標準 (&D)     | @cwebp | $p -preset default -sharp_yuv -af -mt -o $-p_def.webp
> 可逆圧縮 (&L) | @cwebp | $p -lossless -af -mt -o $-p_less.webp


# --- フォルダ ---
[folder]

開く (&O)
> VS Code で開く (&V) | @apps\Microsoft VS Code\Code.exe | -n $p
> ---
> コマンドプロンプトで開く (&C) | C:\Windows\System32\cmd.exe |
 :dir $p

---

IrfanView でサムネイル表示 (&T) | @irfan | /thumbs $p
 :delay 250

# 1 つ開いて、閉じると次が開く（手で 1 件ずつ片付けるとき）
1 つずつ開いて確認 (&R) | @apps\Microsoft VS Code\Code.exe | --wait -n $p
 :wait


# --- 全対象 ---
[file folder]

圧縮 (&Z)
> + まとめて 1 つにする (&A) | @apps\7-Zip\7z.exe | a -t7z $d\archive.7z $p -mx9
> 個別に圧縮 (&S)           | @apps\7-Zip\7z.exe | a -t7z $-p.7z $p -mx9
```
